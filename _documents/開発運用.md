# 開発運用

参考リポジトリの日本語運用、`develop`／`master`、Issue と PR の紐付け、Draft と WIP のゲート、指示同期、セキュリティ検査を、この C# リポジトリ向けに採用しています。初期作成は直接 `develop` に配置し、以後は PR で進めます。

## エージェント

共通の参照元は `.github/copilot-instructions.md` です。Codex は `AGENTS.md`、Claude Code は `CLAUDE.md` から読みます。共通規約を変更したら `bash scripts/sync-agents.sh` で `AGENTS.md` を再生成します。CI が同期を検査します。

一時成果物は `temp/yyyyMMdd_内容/`、並行作業は `git worktree` で `.worktrees/` に置きます。外部メモリを利用する場合も正式な規約の参照元は共通指示です。

## Actions

- CI：全ブランチ push と `develop`／`master` 宛 PR。ロック済み依存の復元、Release ビルド、HTTP テスト、
  指示同期、参照混入チェックとネットワーク不要の参照取得テスト。
- CodeQL：C# を実ビルドで解析。push と週次、手動実行。
- 依存監査：npm と NuGet の推移的依存も push と週次で検査。JSON の脆弱性を判定し、見つかったら失敗する。
- 依存レビュー：PR で追加依存の脆弱性を検査。
- PR タイトル：`WIP:` が残っていれば失敗。Issue 紐付けはログで通知。
- 参照取得：AI が調査する前に `bash scripts/sync-reference.sh` で上流 `main` を取得する。
  Git では追跡せず、CI からの本体取得・日次追従・ポインタ更新 PR は行わない。
- Dependabot：npm、NuGet と GitHub Actions を週次確認。

CI はテスト成功後に配布物を生成し、McpOAuthWrapper Artifact として30日間保存します。アプリ本体、設定例、README、説明資料、LICENSE、LICENSING.md、LICENSE-COMMERCIAL.md、NOTICE、ThirdPartyNotices.txt、ソースのコミット情報を含めます。実際の接続設定、OAuth 状態、秘密鍵と参照専用ソースは含めません。画面は MVC/Razor と SCSS・TypeScript で構成し、npm で静的アセットを生成・検査します。SQL Server・MySQL に接続した Pleasanter 経由の E2E・Claude の E2E、コンテナ／AKS 公開は未実施です。GitHub Releases の生成経路は [リリース手順](リリース手順.md) を参照してください。実際の公開はリリース時に実行します。

## GitHub 設定

### CLA の署名確認と初期配置

本リポジトリはデュアルライセンス（AGPL-3.0-or-later ＋ 商用。[ライセンス](../LICENSING.md)）で提供します。
[CLA](../CLA.md) は、貢献を商用ライセンスでも提供できるようにするためのものです。
署名用 Issue フォームと手続きは [貢献のしかた](../CONTRIBUTING.md) にあります。

`cla` は `pull_request_target` で PR 作者のログイン名を確認し、
**PR の base コミット**の `.github/cla/signed.yml` だけを参照します。
PR のコードは実行せず、外部 CLA サービスも使いません。
未署名なら失敗し、重複しない案内コメントを投稿します。一覧が無い場合はエラーで停止します。

1. 管理者は署名用 Issue で本人の同意と許諾権限を確認する。
   業務での貢献は法人用の同意と法人を代表する権限、対象の貢献者も確認する
2. 管理者の Issue／PR で、署名一覧に `login`・`signed`（署名日）・`type`・`note` を記録する。
   同意の根拠となる Issue は管理者の PR から参照し、秘密情報を記録しない
3. 一覧の変更を対象 base へ取り込んだ後、貢献 PR を更新して再実行する。
   develop と master の一覧は別々に確認する

初期一覧は 2026-10-22 のユーザー指示に従い、`pmc-ko` の法人署名記録1件のみです。
`cla` は PR 作者以外の共同著作者の権利まで自動確認しないため、
管理者が実際の貢献の権利も確認します。
bot の除外は `dependabot[bot]`・`github-actions[bot]`・`my-repo-automation-bot[bot]` の完全一致のみです。
これらもジョブを skip せず成功を報告します（base に署名一覧が必要です）。

**初期配置では GitHub 設定・ルールセットを変更しません。**
base に署名一覧が無いため、導入 PR 自体の `cla` は失敗するか、まだ起動しない可能性があります。
PR 内の署名一覧は当該 PR の判定に使われません。`cla` はまだ必須ではないため、この制約ではマージを妨げません。
必須化はマージ後の別作業とし、対象ブランチごとにワークフローと署名一覧が配置済みであることを先に確認します。
master にも、必須化より先に両ファイルを通常の PR で反映してください。

### 既存の設定と運用

既定ブランチは `develop`、`master` はリリース用です。2026-10-06 に develop-protection／master-protection／release-tag-protection が有効で、develop の削除・強制 push が禁止されていることを確認しました。初期設定時の自動承認レビュー拒否後に利用者が設定した内容を維持します。今回の作業で保護規則は変更しません。

PR の依存レビューは GitHub の Dependency graph が必要です。公開直後には無効でしたが、利用者の設定後に依存レビューが成功することを確認済みです。NuGet の推移的依存監査も動作しています。

参照ソースの取得に bot の App は使いません。patch 更新・リリースタグ作成は引き続き
`my-repo-automation-bot` を使います。`GITHUB_TOKEN` の PR 承認権限は変更しません。
以下は他用途も含む既存設定の説明であり、参照更新の廃止に伴う設定・権限・資格情報の変更は行いません。

- Repository Variables：`MY_REPO_AUTOMATION_BOT_CLIENT_ID`（App の Client ID。App ID ではない）
- Repository Secrets：`MY_REPO_AUTOMATION_BOT_PRIVATE_KEY`（App の PEM 秘密鍵）
- App のインストール対象：このリポジトリ
- App の Repository permissions：Contents／Pull requests／Issues の Read and write

必要な用途の設定は利用者が行います。長期トークンは保存せず、
`actions/create-github-app-token@v3` で対象リポジトリだけに使える短期トークンを発行します。
App の秘密鍵はチャット・ファイル・Git に貼りません。

2026-10-27 の移行では、参照用 gitlink と日次更新 workflow・専用スクリプトだけを削除しました。
既存の参照更新ブランチ・Draft PR・Issue は変更せず、後続の整理に委ねます。
再現性はポインタではなく、文書に残す確認済みの完全な SHA・固定リンク・参照日で保ちます。
未再確認の過去の調査・実機記録を最新ソースの検証結果として扱いません。
取得・隔離・既存 clone の扱いは [参照ソース](../_reference/README.md) を参照してください。

SDK の選択は `global.json`、NuGet の版は csproj と `packages.lock.json` が参照元です。更新時は `dotnet restore --force-evaluate` でロックを更新してコミットします。
