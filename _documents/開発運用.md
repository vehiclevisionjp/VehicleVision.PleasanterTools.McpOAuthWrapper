# 開発運用

参考リポジトリの日本語運用、`develop`／`master`、Issue と PR の紐付け、Draft と WIP のゲート、指示同期、セキュリティ検査を、この C# リポジトリ向けに採用しています。初期作成は直接 `develop` に配置し、以後は PR で進めます。

## エージェント

共通の参照元は `.github/copilot-instructions.md` です。Codex は `AGENTS.md`、Claude Code は `CLAUDE.md` から読みます。共通規約を変更したら `bash scripts/sync-agents.sh` で `AGENTS.md` を再生成します。CI が同期を検査します。

一時成果物は `temp/yyyyMMdd_内容/`、並行作業は `git worktree` で `.worktrees/` に置きます。外部メモリを利用する場合も正式な規約の参照元は共通指示です。

## Actions

- CI：全ブランチ push と `develop`／`master` 宛 PR。ロック済み依存の復元、Release ビルド、HTTP テスト、指示同期と参照混入チェック。
- CodeQL：C# を実ビルドで解析。push と週次、手動実行。
- 依存監査：NuGet の推移的依存も push と週次で検査。JSON の脆弱性を判定し、見つかったら失敗する。
- 依存レビュー：PR で追加依存の脆弱性を検査。
- PR タイトル：`WIP:` が残っていれば失敗。Issue 紐付けはログで通知。
- 参照更新：日次で上流リリースタグを検査し、更新があれば GitHub App の短期トークンで Issue と Draft PR を作成。App の操作から通常の CI が起動する。更新が無いときは App の登録なしで検出を完了できる。
- Dependabot：NuGet と GitHub Actions を週次確認。

フロントエンド、DB 結合テスト、E2E、コンテナ／AKS 公開、商用ライセンス用 CLA のワークフローは、その対象がまだ無いため導入していません。リリースは仕様と配布形式が固まった段階で追加します。

## GitHub 設定

既定ブランチは `develop`、`master` はリリース用です。ブランチ保護は初期設定の自動承認レビューで拒否されたため、まだ未適用です。利用者が Settings → Rules → Rulesets で `develop`／`master` を対象に、削除と強制 push の禁止、PR 必須、CI の「ビルドと単体テスト」「指示と参照の検査」、PR タイトルの「WIP が外れているか」を必須にする設定を行ってください。CodeQL と依存監査は必須にせず、新しい警告が修正 PR 自体を塞がないようにします。

PR の依存レビューは GitHub の Dependency graph が必要です。公開直後には無効で、実行時に「Dependency review is not supported on this repository」と失敗したことを確認しました。Settings → Advanced Security（Code security）で Dependency graph を有効にしてください。NuGet の推移的依存監査はこの設定に依存せず動作します。

参照更新は、参考リポジトリと同じ `my-repo-automation-bot` を使います。`GITHUB_TOKEN` の PR 承認権限は変更しません。

- Repository Variables：`MY_REPO_AUTOMATION_BOT_CLIENT_ID`（App の Client ID。App ID ではない）
- Repository Secrets：`MY_REPO_AUTOMATION_BOT_PRIVATE_KEY`（App の PEM 秘密鍵）
- App のインストール対象：このリポジトリ
- App の Repository permissions：Contents／Pull requests／Issues の Read and write

利用者がこれらを登録します。長期トークンは保存せず、`actions/create-github-app-token@v3` で対象リポジトリだけに使える短期トークンを発行します。App の秘密鍵はチャット・ファイル・Git に貼りません。登録前は実際の更新 PR 作成を検証できません。

SDK の選択は `global.json`、NuGet の版は csproj と `packages.lock.json` が参照元です。更新時は `dotnet restore --force-evaluate` でロックを更新してコミットします。
