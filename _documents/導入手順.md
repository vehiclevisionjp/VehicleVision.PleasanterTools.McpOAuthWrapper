# 管理者向け導入手順

本書は初期版の設定手順です。Pleasanter 実機と AI アプリを通した接続確認は未実施です。まず検証環境で確認してください。

## Pleasanter と DB

Pleasanter の MCP サーバーを有効にし、利用者または共通アカウントの API キーを Pleasanter 本体で発行します。ラッパーへ API キーを入力する設定はありません。

ラッパーの配置先に `App_Data/Parameters/Rds.json` を用意します。付属の Rds.example.json は本体と同じフラットなレイアウトです。Dbms は PostgreSQL／SQLServer／MySQL、Provider は Local。UserConnectionString に Users の必要列だけを SELECT できる専用の読み取り専用接続を設定します。SaConnectionString と OwnerConnectionString は使用せず空にしてください。接続文字列の `#ServiceName#` などのプレースホルダーは展開しません。

UserConnectionString は環境変数 `MCP_RDS_UserConnectionString` でも上書きできます。SqlCommandTimeOut は 1～120 秒に設定します。本体用の管理者接続をそのまま持ち込まないでください。

同じフォルダーに、本体の設定と一致する Authentication.json と Security.json を配置します。設定例はローカル認証・二段階認証なしの構成です。本体で有効な認証機能を、ラッパー側だけ無効にしないでください。初期版は LDAP・パスキー・二段階認証をサポートせず、それらを有効とする設定では起動を拒否します。

## ラッパーの設定

秘密を含まない設定は appsettings.json の Bridge セクションで指定できます。配置ごとの上書きには `Bridge__項目名` の環境変数を使用できます。

| 項目 | 設定内容 |
| --- | --- |
| Enabled | 設定完了後に true。初期値 false では `/mcp` は 501 |
| Issuer | ラッパー専用ホストのルート HTTPS URL。末尾 `/` 必須 |
| PleasanterUrl | 上流 Pleasanter のベース HTTPS URL。サブパス可、末尾 `/` 必須 |
| TenantId | 接続を許可するテナント ID |
| DatabaseTimeZoneId | 本体が DB に日時を保存する際のタイムゾーン。初期値 UTC。日本時間なら Asia/Tokyo |
| SharedApiKeyUserId | 共通アカウントの UserId。同じテナント内に限定。null で個人アカウントのみ |
| StateDirectory | OAuth 状態・暗号化用鍵の永続ディレクトリー。初期値 App_Data/Wrapper |
| SigningCertificatePath / EncryptionCertificatePath | 本番用の秘密鍵付き PFX。期限内の証明書を配置 |
| CertificatePassword | PFX のパスワード。環境変数や配置環境の秘密管理から設定 |
| TrustedProxyAddresses | HTTPS 終端プロキシを使う場合、その送信元 IP の明示的な一覧。1 段の転送ヘッダーを信頼 |
| AllowedOrigins | ブラウザーから MCP へ接続する場合に追加する許可 Origin。完全一致。既定で同一 Origin と Origin なしを許可 |

OAuth の状態領域と証明書をアプリ実行アカウントだけが読み書きできるようにします。初期版は単一インスタンスで運用します。状態領域を消すと発行済みの認可・トークン・セッションを利用できなくなります。

プロキシを使う場合は、Issuer のホストと HTTPS を伝えるヘッダーを設定し、TrustedProxyAddresses を指定します。公開 URL と実際の Host／scheme の不一致は拒否します。入口で本体と同等のネットワーク制限を適用してください。

## AI アプリの登録

事前登録する場合は Clients に ClientId、DisplayName、RedirectUris を指定します。クライアントの redirect URI を実際の設定から確認し、完全一致で登録します。ワイルドカードは使えません。公開クライアントとして Authorization Code + PKCE S256 を使用します。

動的登録を要求するクライアントでは AllowDynamicClientRegistration を true とし、AllowedRedirectUris に同じ完全一致の許可一覧を設定します。登録エンドポイントは `/connect/register` です。動的登録を有効にするだけでは任意の転送先を受け入れません。

AI アプリのコネクタ URL は `Issuer + mcp` です。未認証時の 401 から認可情報を取得し、ラッパーのログイン画面へ移ります。利用者の手順は [README](../README.md) を参照してください。

初期版では、Clients から設定を除いた場合も OAuth DB の既存登録は自動削除しません。クライアントを廃止する際は停止中に状態領域を再作成して全認可を無効化し、残すクライアントを再登録します。全利用者が再接続する必要があります。

## 確認

`/health/live` は起動確認、`/.well-known/oauth-protected-resource` と `/.well-known/oauth-authorization-server` は discovery 用です。個人／共通アカウントで接続し、Pleasanter 側の権限と監査主体、API キー変更・削除、利用者無効化を確認してください。

API キー未発行の場合は本体で発行してから再接続します。キーやアカウントを無効にした場合、次の MCP 通信は拒否されます。既に開始している長時間通信をその場で停止する機能はありません。
