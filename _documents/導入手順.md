# 管理者向け導入手順

本書は初期版の設定手順です。Docker 上の Pleasanter 1.5.8.1／PostgreSQL 17 で OAuth と MCP 接続を確認しています。SQL Server 2025・PostgreSQL 17・MySQL 8.4 の読み取り専用接続と Users の SELECT も Docker で確認済みです。AI アプリの組織コネクタ、Azure App Service・IIS の実機確認は未実施です。まず検証環境で確認してください。

## 1. インストール

Windows または Linux に [ASP.NET Core Runtime 10](https://dotnet.microsoft.com/en-us/download/dotnet/10.0) をインストールします。.NET Runtime だけではなく、ASP.NET Core Runtime が必要です。ソースを変更しない利用者は SDK をインストールする必要はありません。

[Release ページ](https://github.com/vehiclevisionjp/VehicleVision.PleasanterTools.McpOAuthWrapper/releases)から使用するバージョンを選び、リリース説明を確認して Assets の **McpOAuthWrapper.zip** をダウンロードします。Source code (zip)／Source code (tar.gz) はソースコード用で、インストール用の配布物とは異なります。ダウンロードした ZIP を展開してください。

Windows では、例えば `C:\Apps\McpOAuthWrapper` に展開します。Linux では、アプリ実行アカウントが使う配置ディレクトリーに `unzip` で展開します。展開先直下に `VehicleVision.PleasanterTools.McpOAuthWrapper.dll`、`appsettings.json`、`App_Data/Parameters` があることを確認します。`BUILD.txt` には配布物の元となったソースのコミットを記載しています。

まず展開先をカレントディレクトリーにして、接続を無効にした初期設定のまま起動確認します。

```text
dotnet --list-runtimes
dotnet VehicleVision.PleasanterTools.McpOAuthWrapper.dll --urls http://127.0.0.1:5180
```

`http://127.0.0.1:5180/health/live` にアクセスして `Healthy` が表示されれば、アプリの配置とランタイムを確認できています。`/mcp` は接続未設定の 501 を返します。Ctrl+C で停止し、以下の設定を行います。

## 2. Pleasanter とデータベース

Pleasanter の MCP サーバーを有効にし、利用者または共通アカウントの API キーを Pleasanter で発行します。キーはラッパーの接続画面に入力して認証に使います。設定ファイルには登録せず、ラッパーにも保存しません。

ラッパーの配置先に `App_Data/Parameters/Rds.json` を用意します。付属の Rds.example.json は本体と同じフラットなレイアウトです。Dbms は PostgreSQL／SQLServer／MySQL、Provider は Local。UserConnectionString に Users の必要列だけを SELECT できる専用の読み取り専用接続を設定します。SaConnectionString と OwnerConnectionString は使用せず空にしてください。接続文字列の `#ServiceName#` などのプレースホルダーは展開しません。

Windows で設定例を配置する場合は、展開先で次を実行し、作成した2ファイルを構成に合わせて編集します。General.json はラッパー専用の設定、Rds.json は Pleasanter のデータベースへの接続設定です。既存の設定がある場合はコピーせず、内容を確認してください。Linux では同じファイルを `cp` で配置できます。

```powershell
Copy-Item App_Data/Parameters/General.example.json App_Data/Parameters/General.json
Copy-Item App_Data/Parameters/Rds.example.json App_Data/Parameters/Rds.json
```

UserConnectionString は環境変数 `MCP_RDS_UserConnectionString` でも上書きできます。SqlCommandTimeOut は 1～120 秒に設定します。本体用の管理者接続をそのまま持ち込まないでください。

API キーで認証するため Authentication.json／Security.json は使用しません。Pleasanter のパスワードや LDAP・パスキー・二段階認証の設定を変更する必要はありません。API キーを使う接続を組織の運用方針として許可していることを確認してください。

## 3. ラッパーの設定

ラッパーの設定は `App_Data/Parameters/General.json` にフラットな形式で指定します。`appsettings.json` を編集する必要はありません。ファイルと環境変数のどちらにも設定がない場合は接続を無効にして起動します。

配置ごとの上書きには `MCP_GENERAL_項目名` の環境変数を使用できます。例えば証明書パスワードは `MCP_GENERAL_CertificatePassword`、クライアントの項目は `MCP_GENERAL_Clients__0__ClientId` です。環境変数がファイルの設定より優先されます。General.json は Pleasanter からコピーせず、ラッパーに付属する General.example.json を使ってください。

設定例では、利用者や接続元 IP の追加許可リストを設けません。OAuth の PKCE・接続先検証、アカウント状態の検証、ログイン試行制限と MCP の Origin 検証は認証を保護するために適用します。設定が済むまでは Enabled=false とします。

例えば PleasanterUrl に `https://pleasanter.example/portal` を指定すると、`https://pleasanter.example/portal/` として扱い、MCP の接続先は `https://pleasanter.example/portal/mcp` になります。OAuth クライアントの redirect URI は補完せず、登録した値との完全一致で検証します。

| 項目 | 設定内容 |
| --- | --- |
| Enabled | 設定完了後に true。初期値 false では `/mcp` は 501 |
| ApiKeyLoginId | 接続画面の固定ログイン ID。初期値 apikey。1～256文字、サーバー側でも完全一致を検証 |
| Issuer | ラッパー専用ホストのルート HTTPS URL。末尾 `/` は省略可、自動補完 |
| PleasanterUrl | 上流 Pleasanter のベース HTTPS URL。サブパス可、末尾 `/` は省略可、自動補完 |
| TenantId | 接続を許可するテナント ID |
| DatabaseTimeZoneId | 本体がデータベースに日時を保存する際のタイムゾーン。初期値 UTC。日本時間なら Asia/Tokyo |
| SharedApiKeyUserId | 認証したアカウントに加えて選択できる共通アカウントの数値 UserId。同じテナント内に限定。null でこの追加選択肢を表示しない |
| StateDirectory | OAuth 状態・暗号化用鍵の永続ディレクトリー。初期値 App_Data/Wrapper |
| SigningCertificatePath / EncryptionCertificatePath | 本番用の秘密鍵付き PFX。期限内の証明書を配置 |
| CertificatePassword | PFX のパスワード。環境変数や配置環境の秘密管理から設定 |
| TrustedProxyAddresses | HTTPS 終端プロキシを使う場合、その送信元 IP の明示的な一覧。1 段の転送ヘッダーを信頼 |
| AllowedOrigins | MCP リクエストの許可 Origin の追加一覧。完全一致。既定で同一 Origin と Origin なしを許可 |

OAuth の状態領域と証明書をアプリ実行アカウントだけが読み書きできるようにします。初期版は単一インスタンスで運用します。状態領域を消すと発行済みの認可・トークン・セッションを利用できなくなります。

プロキシを使う場合は、Issuer のホストと HTTPS を伝えるヘッダーを設定し、TrustedProxyAddresses を指定します。公開 URL と実際の Host／scheme の不一致は拒否します。入口で本体と同等のネットワーク制限を適用してください。

例えば、同じマシンの HTTPS 終端プロキシから `127.0.0.1:5180` へ転送する場合は、Issuer に公開 URL、TrustedProxyAddresses に `127.0.0.1` を指定します。プロキシは公開ホストの `X-Forwarded-Host` と `X-Forwarded-Proto: https` を送信してください。外部からアプリの HTTP ポートへ直接接続できない配置にします。

本番では署名用と暗号化用の RSA 秘密鍵付き PFX を配置し、そのファイルパスを指定します。これらは OAuth と状態保護に使う証明書で、公開 HTTPS 用証明書は終端プロキシ側で設定します。CertificatePassword とデータベース接続文字列を秘密管理から供給し、配置ファイル・状態領域をアプリ実行アカウントだけが利用できるようにしてください。

アプリ実行環境は Production とします。Windows の起動確認では `$env:ASPNETCORE_ENVIRONMENT = 'Production'`、Linux では `export ASPNETCORE_ENVIRONMENT=Production` を設定してから起動します。開発用証明書を使う Development を本番運用へ流用しないでください。

## 4. AI アプリの登録

事前登録する場合は Clients に ClientId、DisplayName、RedirectUris を指定します。クライアントの redirect URI を実際の設定から確認し、完全一致で登録します。ワイルドカードは使えません。公開クライアントとして Authorization Code + PKCE S256 を使用します。

動的登録を要求するクライアントでは AllowDynamicClientRegistration を true とし、AllowedRedirectUris に同じ完全一致の許可一覧を設定します。登録エンドポイントは `/connect/register` です。動的登録を有効にするだけでは任意の転送先を受け入れません。

AI アプリのコネクタ URL は `Issuer + mcp` です。未認証時の 401 から認可情報を取得し、ラッパーのログイン画面へ移ります。利用者の手順は [README](../README.md) を参照してください。

初期版では、Clients から設定を除いた場合も OAuth データベースの既存登録は自動削除しません。クライアントを廃止する際は停止中に状態領域を再作成して全認可を無効化し、残すクライアントを再登録します。全利用者が再接続する必要があります。

## 5. 起動と確認

設定が完了したら General.json の Enabled を true にし、展開先から再起動します。HTTP 終端プロキシを使う場合の起動コマンドは、最初の起動確認と同じです。

```text
dotnet VehicleVision.PleasanterTools.McpOAuthWrapper.dll --urls http://127.0.0.1:5180
```

常時運用では、このコマンドを配置環境のサービス管理へ登録してください。カレントディレクトリーを展開先に設定し、実行アカウント・秘密の環境変数・状態領域の永続化を指定します。

`/health/live` は起動確認、`/.well-known/oauth-protected-resource` と `/.well-known/oauth-authorization-server` は discovery 用です。個人／共通アカウントで接続し、Pleasanter 側の権限と監査主体、API キー再発行・削除、利用者無効化を確認してください。

API キー未発行のアカウントは最初のログイン認証を通りません。先に Pleasanter で発行してから接続してください。入力したキーから利用者を検索するため、未発行と入力間違いを区別して表示しません。個人キーの認証後に共通アカウントを選び、その共通キーが未発行の場合は発行案内を表示します。キーやアカウントを無効にした場合、次の MCP 通信は拒否されます。既に開始している長時間通信をその場で停止する機能はありません。

## 6. 更新と困ったとき

パスワード認証版から更新した場合は、既存の OAuth 認可を引き継がず、発行済みの API キーで再接続してください。古いトークンは新しい認証方式では拒否します。Authentication.json／Security.json はラッパーで使用しなくなりました。Pleasanter 側のファイルは変更しないでください。

旧版で appsettings.json の Bridge セクションを設定していた場合は、その中の項目を General.json の最上位へ移してください。旧版の `Bridge__項目名` 環境変数は `MCP_GENERAL_項目名` に変更します。

更新時はアプリを停止し、新しい配布 ZIP を別のディレクトリーへ展開します。既存の Rds.json、General.json、証明書、StateDirectory の内容を引き継ぎ、起動確認後に転送先を切り替えます。初期版では OAuth データベースの構造変更を自動移行する仕組みはありません。配布元の変更内容を確認し、データベース構造変更がある更新では再認可が必要になる場合があります。

| 状況 | 確認すること |
| --- | --- |
| 起動時にランタイム不足が表示される | ASP.NET Core Runtime 10 をインストールしたか |
| `/mcp` が 501 | General.json の Enabled が false のままか |
| 接続が 400 | Issuer と公開ホスト・HTTPS・転送ヘッダーが一致しているか |
| ログインできない | 固定ログイン ID、入力した API キー、キー所有者の状態、TenantId。失敗が続いた場合は15分待つ |
| 共通アカウントの API キーが利用できないと表示される | 管理者が指定した共通アカウントのキー発行、アカウント状態、TenantId |
| データベース接続エラー | Dbms、読み取り専用接続、Users の SELECT 権限、ネットワーク経路 |
| AI アプリが接続できない | 登録した redirect URI の完全一致、PKCE S256、公開 URL と証明書 |

## 7. Azure App Service（Windows）

.NET 10 の Windows App Service に配置できます。以下は配置手順であり、Azure 上での実機確認は未実施です。[Microsoft の導入資料](https://learn.microsoft.com/en-us/azure/app-service/quickstart-dotnetcore)も参照してください。

1. Windows／.NET 10 の Web アプリを用意し、HTTPS のみを有効にします。対応するプランでは Always On を有効にします。SQLite の OAuth 状態を使うため、インスタンス数は1に固定します。
2. データベースへの経路を確保します。プライベートな接続先には VNet 統合などを設定し、Users の必要列だけを読める接続を用意します。
3. 配布物を展開し、General.example.json／Rds.example.json をコピーして前述の設定を行います。Issuer は App Service の公開 HTTPS URL です。秘密は App Service のアプリ設定で `MCP_RDS_UserConnectionString`、`MCP_GENERAL_CertificatePassword` として指定します。
4. Kudu で `%HOME%` を確認し、その配下の `data/McpOAuthWrapper` に状態領域と証明書を配置します。General.json の StateDirectory と証明書パスには、その環境の絶対パスを指定します。更新で上書きされる `wwwroot` に状態領域を置かないでください。
5. アプリのファイルを直下に含む ZIP を作り、[ZIP デプロイ](https://learn.microsoft.com/en-us/azure/app-service/deploy-zip)で配置します。DLL と web.config が ZIP 直下に必要です。配置用の General.json はこの私用 ZIP に含めますが、秘密入りの ZIP を公開しないでください。

```text
az webapp deploy --resource-group <リソースグループ> --name <アプリ名> --src-path <配置ZIP> --type zip
```

アプリ設定に `ASPNETCORE_ENVIRONMENT=Production` を指定します。IIS 統合の転送設定は既定のまま利用し、TrustedProxyAddresses は空にします。追加のリバースプロキシを設ける場合だけ、その構成に合わせて明示します。再起動後、公開 URL の `/health/live` と discovery、認可から MCP 接続までを確認します。

## 8. Windows IIS

IIS への配置手順です。IIS 上での実機確認は未実施です。[Microsoft の IIS ホスティング資料](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/iis/?view=aspnetcore-10.0)も参照してください。

1. IIS を有効にした後、.NET 10 の **Hosting Bundle** をインストールし、IIS を再起動します。ASP.NET Core Runtime 単体では IIS 用モジュールが入りません。
2. 配布物を `C:\Apps\McpOAuthWrapper` などに展開します。生成済みの web.config を保持します。
3. 専用のアプリケーションプールを作り、.NET CLR は「マネージドコードなし」、32ビットアプリケーションは無効、ワーカープロセス数は1に設定します。SQLite 状態の同時使用を避けるため、重複リサイクルを無効にします。
4. 専用サイトとして HTTPS バインドと公開用証明書を設定し、配置先とアプリケーションプールを割り当てます。匿名認証を有効にします。Issuer はこのサイトのルート HTTPS URL です。
5. General.json／Rds.json を用意します。StateDirectory は `C:\ProgramData\McpOAuthWrapper\State` など配置先外にし、OAuth 用 PFX も別の保護されたフォルダーへ置きます。公開 HTTPS 用証明書とは用途が異なります。
6. `IIS AppPool\<プール名>` にアプリと証明書の読み取り、状態領域の変更権限を付けます。接続文字列と証明書パスワードは、保護したパラメータファイルまたはアプリプロセスの環境変数で設定します。環境は Production とします。
7. サイトを起動し、公開 URL の health、discovery、OAuth と MCP を確認します。IIS 統合の既定の転送設定を使用する場合、TrustedProxyAddresses の追加設定は不要です。

更新時はサイトを停止するか app_offline.htm を置いて停止を確認し、状態領域・設定・証明書を保持して配布物を更新します。更新完了後に app_offline.htm を削除して再起動します。

## 9. データベース別の設定

Dbms は `SQLServer`／`PostgreSQL`／`MySQL` のいずれかです。接続先の実際のスキーマと Users の読み取り権限を合わせてください。

| データベース | UserConnectionString の例（秘密は例示値） |
| --- | --- |
| SQL Server | `Server=sql.example;Database=Implem.Pleasanter;User ID=mcp_reader;Password=CHANGE_ME;Encrypt=True` |
| PostgreSQL | `Host=pg.example;Database=Implem.Pleasanter;Username=mcp_reader;Password=CHANGE_ME;Search Path='"Implem.Pleasanter"'` |
| MySQL | `Server=mysql.example;Database=Implem.Pleasanter;User ID=mcp_reader;Password=CHANGE_ME` |

PostgreSQL の大文字やピリオドを含むスキーマ名は二重引用符付きで指定します。JSON では内部の二重引用符を `\"` として記述します。SQL Server は接続ユーザーの既定スキーマに Users が見えることを確認します。読み取り対象は TenantId、UserId、LoginId、ApiKey、Disabled、Lockout、LoginExpirationLimit、LoginExpirationPeriod、LastLoginTime の9列です。
