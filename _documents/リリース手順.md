# リリース手順

develop の変更をレビューし、CI と CodeQL が成功した状態で master へ PR を作成・マージします。版番号は Directory.Build.props の VersionPrefix（例：0.1.0）です。変更が必要なら develop 上の PR で更新してから master に反映します。

## 配布物だけを確認する

Actions → Release → Run workflow で dry_run を true のまま実行します。タグがなくても実行できます。ロック済み npm／NuGet の復元、SCSS・TypeScript の生成結果、脆弱性検査、Release ビルド、テスト、ZIP と SHA-256 の生成を検査します。リリース配布物 Artifact から ZIP を確認できます。

Release ワークフローの関連ファイルを変更する PR でも、この公開しない検証が自動で動きます。

## リリースする

Actions → リリースタグ作成 → Run workflow で master を選びます。release_tag は vX.Y.Z または vX.Y.Z-rc.1 を指定します。省略時は VersionPrefix の版を使います。まず dry_run=true で採番を確認し、公開するときに dry_run=false で実行します。

ワークフローは master の CI・CodeQL・依存検査・Redis／Valkey テストの成功を確認し、参考リポジトリと同じ GitHub App でタグを作ります。Variable MY_REPO_AUTOMATION_BOT_CLIENT_ID と Secret MY_REPO_AUTOMATION_BOT_PRIVATE_KEY が必要です。App の Contents: write と、リリース用タグを作成できる権限が必要です。

タグ作成を契機に Release が動き、master に含まれるコミットと VersionPrefix の一致を検証して公開します。GitHub Releases には VehicleVision.PleasanterTools.McpOAuthWrapper-バージョン.zip、VehicleVision.PleasanterTools.McpOAuthWrapper-バージョン.zip.sha256、LICENSE、NOTICE とソース取得リンクを配置します。プレリリースのタグは GitHub でもプレリリース扱いになります。ZIP に設定値・秘密鍵・OAuth 状態・参照用サブモジュールは含めません。

手元から master に含まれるコミットへタグを push しても同じ Release が動きます。GITHUB_TOKEN だけで別ワークフローからタグを作ると Release が起動しないため、タグ作成 Actions は GitHub App の短期トークンを使います。

## 失敗した場合

検査失敗時は公開しません。同じタグへ再実行する場合は Actions の Re-run jobs を使います。タグの付け直しや既存リリースの置き換えは行いません。すでに公開したリリースを変更する必要がある場合は次のパッチ版を用意します。

実際のタグ作成・公開はこの整備作業では実行していません。リリース作成には公開ジョブだけに付与する GITHUB_TOKEN の Contents: write を使います。
