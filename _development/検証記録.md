ブラウザー試験で CSP の form-action がクライアントへのリダイレクトを阻む問題を検出し、OpenIddict による完全一致の検証済みクライアントの戻り先ホストだけを許可するよう修正しました。HTTP テストと再度の実機接続で確認しています。

PostgreSQL のスキーマは `"Implem.Pleasanter"`。Npgsql の接続文字列では `Search Path='"Implem.Pleasanter"'` とし、接続文字列自体の引用と SQL 識別子の引用を区別します。初期化用 CodeDefiner とアプリ用イメージではパラメータの配置先が異なります。前者は `/app/Implem.Pleasanter/App_Data/Parameters`、後者は `/app/App_Data/Parameters` です。Service.json／McpServer.json の一部だけを再作成せず、イメージの設定を読み、検証用の値だけ変更しました。

実機試験ドライバーは [docker-flow.cjs](tests/docker-flow.cjs)。管理者の標準画面で API キーを発行し、ラッパーと専用コンテナを起動してから実行します。検証利用者の作成・API キー再発行を行うため、既存・本番環境へ実行してはいけません。ローカルの環境情報、接続設定、秘密とブラウザー依存は ignored の temp にだけ置きます。

```text
node _development/tests/docker-flow.cjs temp/<検証ディレクトリー>/environment.json
```

環境情報の項目は pg（専用 PostgreSQL コンテナ名）、appPort（Pleasanter のループバック公開ポート）、adminPassword（検証専用の管理者・利用者パスワード）です。同じディレクトリーの browser/node_modules に playwright-core を用意します。ラッパーは `localhost:15154`、`demo-client`、`https://client.example/callback`、`SharedApiKeyUserId=1` とし、実際のブラウザーで許可を操作します。クライアントへの戻り先は検証用画面として捕捉し、Claude の画面や組織コネクタを代替した検証とは扱いません。

公開するのは画面と秘密を含まない検証結果だけです。API キー、パスワード、認可コード、トークンは出力・画像・追跡ファイルに含めません。ベトナム語のカルチャ名は .NET の標準に従って vi です。

SQL Server・PostgreSQL・MySQL の接続と SELECT は、以下の Docker 試験でも確認しています。SQL Server・MySQL に接続した Pleasanter を通した OAuth/MCP 試験は未実施です。Azure App Service・IIS・Claude 組織コネクタ・本番証明書、実データへのツール実行と権限差の確認も未検証です。

## 3種類のデータベースの接続・SELECT

専用の空コンテナに検証用 Users を作成し、アプリの PleasanterConnectionFactory と PleasanterUserStore をそのまま呼び出しました。初期化は検証用の管理者接続で行い、SELECT は別の読み取り専用アカウントで実行しています。

| データベース | 使用イメージ | サーバーバージョン | 接続・SELECT |
| --- | --- | --- | --- |
| SQL Server 2025 | mcr.microsoft.com/mssql/server:2025-CU8-ubuntu-24.04 | 17.0.4075.5 | 成功 |
| PostgreSQL 17 | postgres:17 | 17.11 | 成功 |
| MySQL 8.4 | mysql:8.4 | 8.4.11 | 成功 |

UserId／API キーによる9列の検索、bool／日時／NULL の列変換、異なるテナントと該当なしの検索、SQL 注入文字列での非一致、読み取り専用アカウントの DELETE 拒否を確認しました。ここでの Users は必要列の型を持つ検証用テーブルであり、SQL Server・MySQL を使う Pleasanter の OAuth/MCP 全体の試験とは区別します。

再実行には .NET SDK 10 と Linux コンテナを使える Docker、PowerShell 7 が必要です。リポジトリのルートで次を実行します。毎回、専用コンテナ・ランダムパスワード・ループバックの空きポートを用意し、終了時には自分が作成したコンテナと秘密を含む一時ファイルを削除します。既存のコンテナやデータベースには接続しません。

```powershell
pwsh -File scripts/database-smoke.ps1
```

SQL Server は検証用の Developer エディションを使用します。検証プログラムとロックファイルは `_development/tests/database-smoke` に置き、アプリの配布物には含めません。

## KVS モード

Redis 8.2.10（redis:8.2）と Valkey 9.1.2（valkey/valkey:9.1.2）の専用 Docker コンテナを使いました。API キーを含まない OAuth の状態を実際の KVS ストアで管理し、SQLite を経由しません。KVS モードでは62件、SQLite モードでは通常57件と KVS 専用5件のスキップを確認します。

既存57件に加え、別ホスト・再起動後のトークン利用と失効共有、20並列での同意の一度きり消費、10並列での試行制限共有、2ホストでの認可コード同時交換の一度きり成功、古い版の更新と失効済みトークンの復活の拒否、期限切れ状態と索引の整理を確認しました。KVS に API キーが含まれないことと、ローカルの oauth.db／鍵ファイルが作られないことも検査しています。

複数ホスト試験は同じプロセス内の独立した ASP.NET Core ホストで実施しました。本番での別マシンの共有には同じ証明書が必要です。Redis Cluster・クラウドのマネージド KVS・障害切り替え構成は実機未検証です。

## セキュリティ指摘への対応（#27）

ログイン成功時の試行回数を全消去せず1回分だけ戻す変更、動的登録の冪等化と上限、転送ヘッダーの警告を追加し、単体テスト（SQLite 状態）59件に新規3件を加えた計64件のうち、KVS 以外が合格しました。Valkey 9.1.2 の専用 Docker コンテナを使った KVS 有効の実行では、64件すべてが合格しました。プロキシ警告のログ出力は自動テストを追加しておらず、実機でも確認していません。

## 画面改善・リリース経路

SCSS と TypeScript による新しい Razor 画面を、localhost の合成 Users とテスト用 MCP 中継先で検証しました。実ブラウザー接続が利用できなかったため、専用のヘッドレス Chrome で検査しています。7言語のログイン、個人／共通アカウント同意、ログインエラー、幅390pxの表示、キーの表示・非表示、言語切り替え、JavaScript 無効時のログインが成功しました。JavaScript エラーと CSP 違反は検出されていません。スクリーンショットはこの合成データ環境の実画面で、Claude／ChatGPT の実接続を示すものではありません。

SQL Server の暗号化設定について、省略・False・Optional・True・Strict の5ケースを追加しました。現在は SQLite 64件と KVS 専用5件のスキップ、Redis／Valkey 69件を CI で検査します。以前の57／62件の実機記録は変更していません。

リリース候補 v0.1.0 の版検査、ZIP と SHA-256 の生成、秘密・実設定・参照ソースの除外をローカルで確認しました。実際のリリースタグ作成と GitHub Releases 公開は実行していません。PR の Release ワークフローで公開しない経路も検査します。

認可コードを同時に交換した場合は、再利用検出により認可全体を失効し、両方の交換を拒否する場合があります。HTTP テストは二重発行なし・拒否が invalid_grant・エラー応答にトークンなしを確認します。ストアの原子的な消費は2並列の成功1件と、最新版の再読み込み後の再消費拒否を確認します。根拠：[RFC 6749 §4.1.2](https://www.rfc-editor.org/rfc/rfc6749#section-4.1.2)。参照日：2026-10-06。

## API キーだけのログイン入力（2026-10-08）

固定ログイン ID 欄と ApiKeyLoginId 設定・照合を削除し、フォームは apiKey だけで利用者を認証する形へ変更しました。共通権限の選択、同意、Authorization Code + PKCE、Users の状態検証、API キー非保存は維持します。

通常の Release ビルドは警告・エラー0件で成功しました。Windows サンドボックスでは開発用証明書ストアとイベントログへのアクセスが拒否され、通常設定での HTTP テストは実行できませんでした。検証時だけ開発用証明書をメモリ上の一時署名・暗号化鍵に差し替え、イベントログ出力を無効化した実行では、通常テスト64件が成功し、KVS専用5件をスキップしました。追加の画面撮影用テスト1件も成功しました。検証用の鍵変更と画面撮影用テストは実行後に削除し、通常設定で Release ビルドを再実行しました。KVS・Pleasanter 実機・AI アプリ経由の再検証は実施していません。

ガイドの7言語・エラー・モバイルのログイン画像は、合成 Users を使う HTTP テストから生成した HTML をヘッドレス Chrome で描画しました。撮影用 HTML の hidden 入力を除去し、キーやトークンを画像へ含めていません。変更していない同意画面は従来の合成環境の画像です。

Issue 作成は GitHub 連携の組織 SSO 制限で拒否され、利用者の了承により後回しにしました。実装時点ではサンドボックスで .git が読み取り専用でしたが、利用者のコミット指示後に書き込み権限を取得し、develop から fix/api-key-only-login ブランチを作成しました。PR 作成は未実施です。
