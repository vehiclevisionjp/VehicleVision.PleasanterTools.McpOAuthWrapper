ブラウザー試験で CSP の form-action がクライアントへのリダイレクトを阻む問題を検出し、OpenIddict による完全一致の検証済みクライアントの戻り先ホストだけを許可するよう修正しました。HTTP テストと再度の実機接続で確認しています。

PostgreSQL のスキーマは `"Implem.Pleasanter"`。Npgsql の接続文字列では `Search Path='"Implem.Pleasanter"'` とし、接続文字列自体の引用と SQL 識別子の引用を区別します。初期化用 CodeDefiner とアプリ用イメージではパラメータの配置先が異なります。前者は `/app/Implem.Pleasanter/App_Data/Parameters`、後者は `/app/App_Data/Parameters` です。Service.json／McpServer.json の一部だけを再作成せず、イメージの設定を読み、検証用の値だけ変更しました。

実機試験ドライバーは [docker-flow.cjs](tests/docker-flow.cjs)。管理者の標準画面で API キーを発行し、ラッパーと専用コンテナを起動してから実行します。検証利用者の作成・API キー再発行を行うため、既存・本番環境へ実行してはいけません。ローカルの環境情報、接続設定、秘密とブラウザー依存は ignored の temp にだけ置きます。

```text
node _development/tests/docker-flow.cjs temp/<検証ディレクトリー>/environment.json
```

環境情報の項目は pg（専用 PostgreSQL コンテナ名）、appPort（Pleasanter のループバック公開ポート）、adminPassword（検証専用の管理者・利用者パスワード）です。同じディレクトリーの browser/node_modules に playwright-core を用意します。ラッパーは localhost:15154、demo-client、https://client.example/callback、SharedApiKeyUserId=1 とし、実際のブラウザーで許可を操作します。クライアントへの戻り先は検証用画面として捕捉し、Claude の画面や組織コネクタを代替した検証とは扱いません。

公開するのは画面と秘密を含まない検証結果だけです。API キー、パスワード、認可コード、トークンは出力・画像・追跡ファイルに含めません。ベトナム語のカルチャ名は .NET の標準に従って vi です。

SQL Server・MySQL は専用ドライバーと SQL の引用を実装し、ドライバー選択を自動テストで確認しています。両データベースの実機互換性は未検証です。Azure App Service・IIS・Claude 組織コネクタ・本番証明書、実データへのツール実行と権限差の確認も未検証です。
